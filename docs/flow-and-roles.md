# Flow และสิทธิ์ระบบหอพัก

ตรวจจากโค้ดวันที่ 27 กันยายน 2569 ไม่ได้อ่านรายชื่อบัญชีหรือบทบาทจากฐานข้อมูล production

## ลูกบ้าน

เข้า LINE → ผูกห้องจากลิงก์ของสาขา → หน้าหลักเลือกบิลค้างเก่าที่สุด → ดูยอดคงเหลือ → QR PromptPay → โอนผ่านธนาคาร → แนบสลิปและเวลาที่โอน → เจ้าหน้าที่ตรวจ → แสดงผลในบิลและประวัติ

- ยังไม่มีบิล: หน้าหลักแสดงข้อความและทางไปประวัติ ไม่แสดงเป็นข้อผิดพลาด
- บิลของฉัน: เริ่มที่ยังชำระไม่ครบ เปลี่ยนไปชำระครบหรือทั้งหมดได้ ยอดคงเหลือหักเฉพาะสลิปอนุมัติ
- รอตรวจสลิป: แสดงว่าได้รับหลักฐานแล้ว ไม่ขอให้โอนซ้ำ
- ประวัติ: เรียงตามวันที่ส่งสลิป ค้นหาตามเดือน/เลขบิล และกรองตรวจผ่าน รอตรวจ ไม่ผ่าน
- รายละเอียดบิล: แสดงหลักฐานแต่ละครั้ง เหตุผลที่ไม่ผ่าน เลขใบเสร็จ และลิงก์เปิดสลิปเมื่อมีข้อมูล
- ผู้เช่าดูเฉพาะข้อมูลตนเองผ่าน resident JWT ตรวจ residentId, storeId และ branchId บน API

## Backoffice

เลือกสาขา → เลือกรอบบิลในกราฟการชำระ → กดสถานะ → รายชื่อห้อง/ผู้เช่า → ดูบิลที่กรองตรงเลขบิล หรือไปตรวจสลิป

กราฟนับบิลที่ออกแล้วเท่านั้น ไม่รวม DRAFT/VOID มี 5 สถานะที่ไม่ซ้อนกัน: ชำระครบ รอตรวจ ชำระบางส่วน ยังไม่ชำระ เกินกำหนด วันครบกำหนดเทียบปฏิทินประเทศไทย บิลที่ส่งสลิปแล้วอยู่กลุ่มรอตรวจก่อนแม้พ้นกำหนด เพื่อป้องกันการทวงซ้ำ

กราฟแนวโน้ม 6 เดือนเป็นยอดตามรอบบิล ไม่ใช่กระแสเงินสดตามวันที่โอน รายการหนึ่งคือหนึ่งบิล ผู้เช่าที่มีหลายห้องอาจปรากฏหลายรายการ

## บทบาท

ระบบเดิมสร้าง Owner และ SUPER_ADMIN จาก seed/migration บทบาทผู้จัดการที่เคยอยู่ในหน้าตัวอย่างเป็นเพียง fallback UI จึงไม่ยืนยันว่ามีในฐานข้อมูลจริง

| บทบาท | สิทธิ์ |
|---|---|
| SUPER_ADMIN | จัดการร้านค้า Platform และบทบาทผ่าน endpoint PlatformOnly ข้อมูลการเงิน/ห้องของ endpoint ทั่วไปยังอิงร้านในบัญชี |
| Owner | งานภายในร้านและสาขาที่ได้รับสิทธิ์ รวมสมาชิกทีม แต่แก้ไข/สร้างบทบาทผ่าน API PlatformOnly ไม่ได้ |
| ผู้จัดการหอพัก (เพิ่มใน migration นี้) | อาคาร ห้อง ผู้เช่า สัญญา มิเตอร์ ออกบิล ตรวจสลิป แจ้งเตือน ตั้งค่ารับเงิน รายงาน และจัดการสมาชิกทีมในขอบเขตของตน |
| การเงิน (เพิ่มใน migration นี้) | ดูห้อง/ผู้เช่า ออกบิล ตรวจสลิป แจ้งเตือน ดู/ส่งออกรายงาน ไม่มีสิทธิ์จัดการสมาชิกทีม |
| ดูรายงาน (เพิ่มใน migration นี้) | ดูห้อง ผู้เช่า บิล สลิป และดู/ส่งออกรายงาน แก้ไข ออกบิล หรืออนุมัติไม่ได้ |
| บทบาทกำหนดเอง | สิทธิ์ตาม permissionKeys ที่ Platform Admin กำหนดและขอบเขตสาขาของบัญชี |
| ลูกบ้าน | ใช้ resident session แยกจากทีมงาน ดูบิล/หลักฐานและส่งสลิปของตนเอง |

บทบาทไม่ได้แทนขอบเขตข้อมูลโดยลำพัง: user.allBranches และ UserBranch เป็นตัวจำกัดสาขา API บังคับ permissions ทุกครั้ง เมนูแสดงตาม permission ของบัญชีจริง

## จัดการสมาชิก

หน้าสมาชิกทีมมีค้นหาและตัวกรองสถานะ สร้าง/แก้ไขชื่อ บทบาท สาขา และสถานะใช้งาน/พักบัญชีได้ตาม user.create/user.update

- รายการ role ที่มอบหมายดึงจาก /users/assignable-roles จึงไม่ติดข้อจำกัด /roles ที่เปิดเฉพาะ Platform Admin
- API ไม่ให้มอบหมายสิทธิ์หรือสาขาที่ผู้ดำเนินการไม่มี
- ไม่แก้ไขบัญชีระบบหรือบัญชีตนเองจากหน้าสมาชิกทีม
- เมื่อพักบัญชี ยกเลิก refresh sessions และ access JWT ผ่านไม่ได้เพราะสถานะไม่ ACTIVE
- ไม่ลบบัญชีถาวรและไม่เปลี่ยนรหัสผ่านใน flow นี้
- preset ไม่เปลี่ยนบัญชี/สิทธิ์ของผู้ใช้เดิม ต้องเลือกมอบหมายเมื่อเพิ่มหรือแก้ไขสมาชิก

## การตรวจสอบ

ผ่าน API 23 tests, Miniapp 12 tests และการคำนวณ Backoffice 4 tests รวมถึง build ทั้ง 3 แอป

ตรวจ UI ด้วยข้อมูลตัวอย่าง: กดกราฟรอตรวจ/เกินกำหนด, เปิดบิลที่กรองตรงรายการ, เปลี่ยนสถานะสมาชิกจำลอง, เปิดบิลลูกบ้าน/หน้าชำระ/ประวัติ และสลับธีม โดยไม่แก้บัญชี production

Unit tests ครอบคลุมยอดอนุมัติ การชำระบางส่วน สลิปรอตรวจ/ไม่ผ่าน วันครบกำหนดไทย การจำกัดสิทธิ์/สาขา บัญชีระบบ และการพักบัญชี ใช้ข้อมูลจำลองเพื่อตรวจ UI โดยไม่มีการโอนเงินหรืออนุมัติสลิปจริง

การใช้งาน LINE และการส่งสลิป production ยังต้องมี LIFF, LINE integration, PromptPay และ Cloudinary ของสาขาที่ถูกต้อง รายการบทบาทใหม่ต้องใช้ migration 20260927000100_staff_role_presets
